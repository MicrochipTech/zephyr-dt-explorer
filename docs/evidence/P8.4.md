## Data model (decision)

* `DraftChild` (new, `core/draft.py`) next to `DraftNode`, not a recursive `DraftNode`: a child has no class, roles, pins or use, and a node-with-everything would invite those fields onto bus devices. `DraftChild` = `name`, `unit` (the text after `@`), `compatible` (list), `labels` (list), `props` (dict in the value model of `core/translate.py`: bool, int, str, lists, `Ref` for phandles, `[[Ref, cell, ...]]` for phandle arrays), `children` (recursive: mdio -> `ethernet-phy@0`). `DraftNode.children: list[DraftChild]`.
* JSON schema version 2: each node has `children`; a `Ref` is stored as `{"ref": "<label>"}`. `Draft.from_dict` reads versions 1 and 2 (a version 1 node gets `children = []`); a loaded draft is version 2, so saving migrates the file. Other versions are still rejected.
* lift: for each covered node the children (recursively) that have at least one property from the board or the app (origin comments, `soc`/`module` origins excluded) become `DraftChild`; the phandle number (`phandle`) is left out (dtc makes it from the labels), phandles and phandle arrays are read through edtlib (label of the target node, cells in binding order), undeclared properties through dtlib. A property that cannot be held (path, reference to a node without a label) is a `not_representable` entry with the child's path. `LiftReport.children` lists the source paths; those nodes no longer appear under "uncovered".
* render: children are written inside the parent override after its properties, with labels, `compatible`, `reg` in hex, properties, grandchildren; `#address-cells = <1>; #size-cells = <0>;` are added when a child has a unit address and neither the properties nor the binding give them.
* translate: `Translation.translate_children` passes children through unchanged (copies); an optional `children:` list per translation entry (`match: {compatible, name}`, `target`, `drop_node`, the usual `keep`/`properties`/`use` rules) translates matching children and their descendants; `reg` and `status` are kept unless a rule says otherwise; a changed `reg` changes the unit address. No built-in translation defines child rules yet (the ADC/DAC/PHY cards add them).
* port: `_port_children` takes the draft node's children through the translation and decides per top-level child for the target bus: exists (same node name in the target bus: stays, note in section 1), refused (unit address used by another child, label already in the target, reference to a label the target lacks: `not carried` with the reason), else written inside the ported bus (and listed as `carried`, with the source file and line of the child). Labels that point to ported nodes are mapped. The app-overlay carry skips the source paths decided here (no second copy), and still handles everything else; children of a bus that is not ported and enabled are reported as `not carried` (board-defined ones by a final pass, app-defined ones by the carry path as before), so nothing disappears silently. The `child nodes ... stay in the source build` lines of section 5 are gone.
