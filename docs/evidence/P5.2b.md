## 1. Findings that shaped the translation

- The target bindings are `dts/bindings/i2c/microchip,sercom-g1-i2c.yaml` and `dts/bindings/spi/microchip,sercom-g1-spi.yaml` in Zephyr main. They include `i2c-controller.yaml`/`spi-controller.yaml` and `pinctrl-device.yaml`.
- Pad configuration: the g1 SPI binding uses the **same** `dipo`/`dopo` (int, required) as `atmel,sam0-spi`. Both drivers pass them unchanged into `SERCOM_SPI_CTRLA_DIPO/DOPO` (`spi_sam0.c:739`, `spi_mchp_sercom_g1.c:1090`). The g1 I2C binding has no pad properties (as the old one). No derivation or hook is needed for them.
- The pic32cx_sg41 SoC dtsi (`pic32cx_sg.dtsi`) and the sam_d5x_e5x SoC dtsi both declare each SERCOM with `compatible = "microchip,sercom-g1"` plus `reg`, `interrupts`, `interrupt-names`, `clocks`, `clock-names`. The board file overrides the compatible with `-i2c`/`-spi`/`-uart`. The clock macros come from the same header `mchp_sam_d5x_e5x_clock.h` that P5.2 generated its tables from, so the existing `clocks_to_periph` hook is correct for both. Test `test_translated_i2c_spi_values_equal_the_sg41_soc_values` checks clocks, interrupts and `reg` base of sercom4/sercom7 against the sg41 SoC dtsi.
- Mapping: every property is `keep` except `clocks`/`clock-names`/`atmel,assigned-clocks` (derive, group `sercom_clocks`) and `atmel,assigned-clock-names` (drop). `dmas`/`dma-names` are kept without the UART warning because both g1 drivers do use DMA. Target-only: `run-in-standby-en` (I2C, default 1), `zephyr,transfer-timeout-ms` (I2C), and `ranges`, `dma-coherent`, `dma-ranges` (base.yaml additions after v4.3.0, both).
- Capability selection: the YAML holds two entries per source, the real translation and the `no_target` one. The registry keys are `(source, target)` and `(source, None)`. A consumer picks the real one if the target binding exists in the target workspace (test helper `select_translation`), otherwise the `no_target` entry, whose report line says `no target binding in this workspace (... Zephyr v4.3.0 ...)`.
