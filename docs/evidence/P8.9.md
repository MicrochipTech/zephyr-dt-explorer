## Design

* One recipe `microchip_gmac` for `atmel,sam0-gmac`, `atmel,sam-mdio`, `microchip,gmac-g1-eth`, `microchip,gmac-g1-mdio`.
  Two draft nodes: MAC (class `ethernet`, roles = ATDF signal names) and MDIO bus (class `mdio`, roles `MDC`/`MDIO`) with
  the PHY as `DraftChild` (`ethernet-phy@<addr>`, label `phy`); `phy-handle` on the MAC. Both are label overrides, so the
  different tree shape of the ports does not matter. `make_nodes()` builds them; the recipe calls `draft.register_class` for
  `ethernet-controller.yaml` and `mdio-controller.yaml` so that `lift_build` finds the classes.
* RMII: the 8 roles each have exactly one candidate pad in the ATDF -> `auto_pins` marks them `automatic`. MII extras only
  with `mii=True`; `derived_props` then derives `phy-connection-type = "mii"` (RMII derives nothing: default of both bindings).
* MDC/MDIO: four IOSET pairs (PB14/PB15, PC11/PC12, PC22/PC23, PA20/PA21) are all returned as alternatives. Default: the
  pair the node has now (`current`) if no other node uses it, else the lowest IOSET without a pad in use, else the lowest
  with a note. On SG41 `used` (other nodes) contains PB14/PB15 (TC5 PWM); the board's own pair PC22/PC23 is the default
  when `current` comes from the build; without that hint the default is PC11/PC12 (shown in the output below).
* Kconfig (all symbols checked to have a prompt in the Kconfig tree of the right workspace, output below):
  `CONFIG_NETWORKING`, `CONFIG_NET_L2_ETHERNET`, `CONFIG_ETH_DRIVER` + driver symbol (`ETH_MCHP_GMAC_G1` / `ETH_SAM_GMAC`);
  mdio: `MDIO_MCHP_GMAC_G1` / `MDIO_ATMEL_SAM`. Not listed: `PHY_GENERIC_MII` (default y via `DT_HAS_ETHERNET_PHY_ENABLED`),
  `NVMEM` (implied), `NET_BUF_FIXED_DATA_SIZE` (choice default), TCP/IP, sockets, TLS. Experiment on the SG41 build (verify
  with `CONFIG_NETWORKING=y` alone, with `+NET_L2_ETHERNET`, with `+ETH_DRIVER`) gave the same `.config` each time
  (`ETH_MCHP_GMAC_G1=y MDIO_MCHP_GMAC_G1=y PHY_GENERIC_MII=y NVMEM=y`), because the Microchip boards `configdefault ETH_DRIVER`;
  the table lists `ETH_DRIVER` and `NET_L2_ETHERNET` anyway so that it also works on a board without that default.

## Scope widening (builder decision after the section 4 stop)

* `dt_explorer/core/lift.py`: node-level properties now go through `_child_value` (the function that already served child
  nodes), so `phy-handle` and `mac-eeprom` are lifted as `[Ref(label)]`; the node's own `phandle` number property is skipped
  like for children. One-line change in the property loop plus the skip; no vendor terms added.
* `tests/test_lift.py::_prepare`: the draft is filtered to uart/i2c/spi (that test compares the SERCOM nodes; the repo ATDF
  fixture has no GMAC). The lab1 round-trip in `test_gmac_recipe.py` no longer adds phandles by hand: the lifted gmac holds
  `phy-handle = [Ref(phy)]` (neutral) and `mac-eeprom = [Ref(eeprom)]` (vendor) and compiles; phandle targets are compared
  by node path.
