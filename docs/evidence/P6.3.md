## What changed
* port_report.py: before a node is emitted it is compared with the target board. Status `conflict` (node not emitted, section-1 lines `conflict: <reason>` per reason, `not emitted; ... (not moved: chosen/aliases)`, `suggestion: ...`) for (a) target node enabled with another compatible (target's chosen/aliases named), (b) a ported pad used by another enabled node of the target build, (c) a pad not on the target package / not a pad of the device. Node references in src/ to a conflicting node get problem `conflict` instead of resolving silently to the other node (labels) or getting an alias onto it (aliases). Suggestion (text only): target pads at the same connector pins (board_desc), instances that can mux them for the same roles (provider device model + recipe `valid_assignments`), target pads already used named.
* `_adopt_west_topdir`: the target BuildModel assumed west topdir = ZEPHYR_BASE.parent; for an app in the RTOS4 workspace built against zephyr-main this made every relative board file name unresolvable, so `pins.used_pins` of the target saw none of the board's pinctrl users (30 unresolved pinmux, e.g. sercom6 on PD08/PD09 invisible) and check (b) could not fire. port_build now takes WEST_TOPDIR from the target's CMakeCache. Root cause is in core/build.py (outside this card's scope), see report.
* ui/port.py: status line counts conflict nodes. tests/test_port_report.py: +9 tests; one existing test (pad that the instance lacks) now clears the fake target users because its pads P1/P2 are rightly a (b) conflict with /t/u0.
