## What was built

* `dt_explorer/core/apply.py` (new, no vendor terms): `plan_apply(app_dir, target_board, overlay, conf, single_soc=,
  source_board=)` returns per file the path, whether it exists, "identical", "comment only" and a unified diff
  (`difflib`); `apply(plan, overwrite=set())` writes only new files, a file that exists only when the caller names it (path or
  kind) in `overwrite`; comment-only content (no statement after removing `/* */`, `//`, `#`) is never written; it only writes
  `<app>/boards/<file>`; `source_board` equal to the target is refused. Helpers: `board_file_stems`, `target_of(build)`,
  `app_dir_of(build)`, `single_soc_of(board.yml)`, `plan_lines`.
* `dt_explorer/ui/port.py`: "Apply to app..." button under the verify block of the port result: shows app, target board and
  per file NEW / EXISTS / SKIP (comments only) / identical, the diff for an existing file with a "Replace the existing ..."
  checkbox (off), a "Write files" confirmation, the result lines and the hint `west build -b <target board> <app>`
  (or "New build..."). The app is the source build's `APPLICATION_SOURCE_DIR`.

## Board-file naming rule (source: Zephyr v4.3.0 in the RTOS4 workspace, `zephyr/cmake/modules`)

* `configuration_files.cmake:42` (Kconfig) and `:72` (overlay): `zephyr_file(CONF_FILES ${APPLICATION_CONFIG_DIR}/boards ...)`.
* `extensions.cmake:2807-2813`: names from `zephyr_build_string(filename_list SHORT shortened_filename_list BOARD ...
  BOARD_REVISION ... BOARD_QUALIFIERS ... MERGE REVERSE)`, `.overlay` / `.conf` appended at `:2823-2829`.
* `extensions.cmake:1716-1719`: qualifiers split at `/`, joined with `_` after the board; revision appended with `.` -> `_`;
  `:1721-1727` MERGE adds the revision-less name; `:1734-1740` SHORT drops the first qualifier (the SoC).
* Short form `<board>` allowed only for single-SoC boards (`:2857-2858` overlay, `:2904-2905` conf: FATAL_ERROR "defines
  multiple SoCs"); long and short file together is a FATAL_ERROR (`:2864`, `:2911`).
* Rule used: `sam_e54_xpro/atsame54p20a` -> `boards/sam_e54_xpro.overlay` / `.conf` when `board.yml` lists exactly one SoC (here
  yes), else `boards/<board>_<qualifiers with / -> _>.overlay`. An existing file under the other accepted name counts as
  "exists" (so no conflicting second file). No revision in the name: it applies to every revision.

* Since P5.4 the port of lab1 emits `&sercom4` (SPI) and `&sercom7` (I2C) as translated nodes (the P5.4/P5.4b evidence listed
  them as `no_target`); this comes from other, parallel work in the checkout (translations/recipes), not from P5.6. The full
  build of the copy with that overlay still links.
* The port reports `my_led0` as carried (P5.4b), so the first-apply overlay is not empty; the `.conf` of lab1 holds only
  comments, so only the overlay is written and the UI says so.
* A second apply with an identical result shows no diff by design ("identical"); the diff appears as soon as the
  existing file differs.
