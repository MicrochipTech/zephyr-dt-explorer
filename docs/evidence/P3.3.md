## 1. Rendered SERCOM2 block vs the board block (edtlib compare)

Method: the draft node is built by lifting the real sercom2 node (recipe.lift on rxpo/txpo and the pads of the board pinctrl group), then rendered with the registered recipe and formatter. The build's `zephyr.dts` has every board setting of sercom2 removed (compatible back to `atmel,sam0-sercom`, status disabled, no rxpo/txpo/current-speed/pinctrl, no chosen entries, pinctrl group node deleted). The overlay is appended, cpp (SDK gcc) expands the pinmux macros, edtlib parses the result. The sercom2 node of that EDT is compared with the original build's edt.pickle. `reset` differing from `original` shows the compare is not vacuous; pinmux values are resolved numbers (0x3391, 0x3381).

## Note on the one failure in the whole-suite run

`tests/test_west_tools.py::test_list_boards_rtos4_default_vendors_from_providers` fails in the full run, outside this card. Cause: test-order pollution. `tests/test_microchip_atdf.py` (and other test files) call `plugins.unregister_all()`; the later `load_plugins()` in the west_tools test imports modules that are already imported, so providers are not registered again and `board_vendors()` is `()`. Reproduced without any P3.3 file (`git stash -u`):

```
py -m pytest tests/test_microchip_atdf.py tests/test_west_tools.py -q -k "atdf or vendors_from"
FAILED tests/test_west_tools.py::test_list_boards_rtos4_default_vendors_from_providers
1 failed, 18 passed, 8 deselected
```

Run alone, the test passes (9 passed in tests/test_west_tools.py). Fix belongs to that test file (re-register the providers in the test), not to P3.3.
