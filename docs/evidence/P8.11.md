# P8.11 evidence: check rules for pin function and channel clashes

Build: `_soltest/apps/lab1_leer/build_same54_xpro` (RTOS4 workspace; overlays are strings, nothing is written to the build). Env: DTX_RTOS4_WS, DTX_MAIN_WS, DTX_DESIGN_FILES set.

## Rules
1. `analog_digital_pad` (warning; info `_existing` when the overlay is not involved): an ADC channel's `zephyr,input-positive`/`-negative` selects a pad (device model: signal group AIN, index N, instance matched by base address) that another node uses digitally (GPIO or non-analog pinctrl function). The converter needs no pinctrl entry for this, so the existing `pin_conflict` check does not see it. Analog plus digital pinctrl on one pad is already a `pin_conflict` error and is not repeated.
2. `adc_channel_duplicate` (error): two channels of one ADC with the same `reg` or the same (input-positive, input-negative) pair.
3. `pwm_channel_duplicate` (error): two `pwms` entries on one channel of one controller.
4. `interrupt_line_shared` (warning): interrupt GPIOs (int-gpios, irq-gpios, interrupt-gpios, gpios of gpio-keys children) on different pads with the same EXTINT line number.

Classification tables (generic names, in validate.py): ANALOG_SIGNAL_GROUPS, ANALOG_INPUT_GROUP, INTERRUPT_LINE_GROUPS. No provider or device.py change.

## Vendor-term grep on core/validate.py
