# P7.2 Connector types and detection

## Design choices

- `detect(netlist_pins, pin_count=None) -> float`: `netlist_pins` is a mapping connector pin -> net name (`None`/`""` = unconnected). Keys `str` or `int`, normalised with `str(key).strip()`. The importer card (P7.3) must pass the physical pin key of the connector type: `"1".."20"` (xplained_pro_ext), `"1".."16"` (mikrobus: 1-8 left row AN..GND, 9-16 right row PWM..GND), Arduino labels `"A0".."A5"`, `"D0".."D15"`, `"3V3"`, `"5V"`, `"GND"`, ... (the four Arduino headers are separate PCB parts; the importer must merge them). `pin_count` optionally overrides `len(netlist_pins)`.
- `nexus_map()` (extra, not in the protocol): Zephyr gpio-map index -> pin key. Xplained Pro index n = pin n+3; mikroBUS 0..5 = pins 1..6, 6..11 = pins 9..14; Arduino 0..5 = A0..A5, 6..21 = D0..D15.
- Score weights. xplained_pro_ext: 20 pins 0.2; GND on 2, GND on 19, VCC on 20, "ID" in the net of pin 1: 0.1 each; names (SDA/SCL/RX/TX/MOSI/MISO/SCK/PWM/IRQ on the standard pins) 0.4 saturating at 5 hits; minus 0.1 per GND/VCC net on a signal pin. mikrobus: 16 pins 0.2; 3V3/GND/5V/GND at 7/8/15/16 0.1 each; names 0.4 saturating at 6 hits. arduino_uno_r3: signal labels present 0.45; GND/3V3/5V nets 0.1 each; names on D0, D1, D11-D15 0.25.
- Thresholds used in tests: own type >= 0.8 with typical named nets; every other type < 0.35; random 20-pin connectors < 0.35 (observed max 0.2). A real board whose signal nets are bare MCU pin names scores 0.6 (pin count + GND/VCC positions + ID), so the importer should accept >= 0.5.
- Surprise: the Zephyr nexus numbering is not the physical numbering (Xplained Pro index 0 = pin 3; mikroBUS skips the power pins; Arduino has no pin numbers), hence `nexus_map()`.
