`DTX_DESIGN_FILES=C:\Masters\board_design_files`; main build `%TEMP%\dtx_main_sg41` (pic32cx_sg41_cult, hello_world, cmake only).

## Change

`dt_explorer/recipes/atmel_sam0_sercom.py`: `G1_CLASSES` maps `microchip,sercom-g1-uart/-i2c/-spi` to the
classes uart/i2c/spi; roles, derived props (`rxpo`/`txpo`, `dipo`/`dopo`), `lift`, `valid_assignments` are shared
(the g1 bindings declare `rxpo`/`txpo` with the SAMD5/E5 table and `dipo`/`dopo` as in sam0). `CLASSES` and the sam0
`KCONFIG` entries are unchanged; `kconfig()` without argument still returns the union of the three sam0 tables.

### g1 Kconfig table (verified in `zephyr-main/zephyr`)

| compatible | table | source |
|---|---|---|
| microchip,sercom-g1-uart | `CONFIG_SERIAL=y` | `drivers/serial/Kconfig` (`menuconfig SERIAL`, prompt); driver symbol `UART_MCHP_SERCOM_G1` in `drivers/serial/Kconfig.mchp` is promptless, `default y`, `depends on DT_HAS_MICROCHIP_SERCOM_G1_UART_ENABLED` |
| microchip,sercom-g1-i2c | `CONFIG_I2C=y` | `drivers/i2c/Kconfig` (`menuconfig I2C`); `I2C_MCHP_SERCOM_G1` in `drivers/i2c/Kconfig.mchp`: promptless, `default y`, `depends on DT_HAS_MICROCHIP_SERCOM_G1_I2C_ENABLED` |
| microchip,sercom-g1-spi | `CONFIG_SPI=y` | `drivers/spi/Kconfig` (`menuconfig SPI`); `SPI_MCHP_SERCOM_G1` in `drivers/spi/Kconfig.mchp`: promptless, `default y`, `depends on DT_HAS_MICROCHIP_SERCOM_G1_SPI_ENABLED` |

The `*_MCHP_SERCOM_G1` symbols are deliberately not in the table: they are promptless, and Zephyr's
`scripts/kconfig/kconfig.py` (`check_no_promptless_assign`) aborts the build when a conf file assigns a promptless
symbol. The devicetree node switches them on.

## Findings

* SG41 works end to end: the ATDF provider locates PIC32CX1025SG41128, the g1 formatter (`for_workspace(ws, soc)`)
  resolves the headers, and `validate()` reports only `pin_conflict_existing` info rows from the board itself.
* The overlay needs `RenderContext.bindings` (as `ConfigSession` passes it) to get `#address-cells`/`#size-cells`
  for the I2C node; without it `validate()` reports a missing-property error. Not a recipe issue.
