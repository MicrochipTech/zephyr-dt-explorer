# P5.3 evidence: lift a whole build into a draft

Environment: `DTX_RTOS4_WS=C:\Masters\26020_RTOS4\zephyrproject`, `DTX_DESIGN_FILES=C:\Masters\board_design_files`, builds `apps\lab1` and `apps\lab3` (`build_same54_xpro`, old port), Zephyr SDK 0.17.4 (cpp), `py` launcher. Output below is complete and unfiltered.

Method (reused from P3.3): the lifted draft is rendered (`report.render_context(device)` + `render_overlay`). For each covered node the build's `zephyr.dts` has every board/app-written property of that node removed (origin not SoC), its pinctrl group nodes deleted, and its chosen/alias entries deleted; compatible/status are reset to the SoC default. cpp + edtlib compile the stripped base ("reset") and base + overlay ("rendered"); the node is compared with the original `edt.pickle` on compatible, status, every board-written property (raw bytes), pinctrl-0 resolved pinmux numbers, chosen, aliases. "reset differs from original: True" shows the compare is not vacuous. Then the whole draft is rendered at once on a base with all covered nodes stripped. Pin order inside a pinmux group is compared sorted (render writes role order, the board file may use another; the set is the same). For nodes with child nodes the reset state keeps `#address-cells/#size-cells` (edtlib cannot parse the children otherwise); the rendered state does not, so the overlay must supply them.
