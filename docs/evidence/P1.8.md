## Findings

1. **Entry-point discovery is not wired up.** `discover_entry_points()` exists in `core/plugins.py` but no
   code calls it (`grep -rn discover dt_explorer` finds only its definition). CONTRIBUTING.md states this.
   The CONFIGURATOR.md statement "belongs in the first version" is therefore not yet met.
2. **Translation entry points do not fit YAML sets.** The `dt_explorer.translations` group instantiates
   objects that implement `BindingTranslation`, but a translation set is a YAML file loaded with
   `register_file()`. CONTRIBUTING.md says so and does not promise YAML entry points.
3. **Recipe reference file is not on master.** `dt_explorer/recipes/atmel_sam0_sercom.py` does not exist in
   this worktree. CONTRIBUTING.md names it as the reference and says it may not be on the main branch yet.
4. **Existing vendor names in core/ and ui/** (the rule in CONTRIBUTING.md is violated today; this card does
   not change code):
   - `dt_explorer/core/build.py:209`: `"atmel"` in a tuple of ignored vendor folders
   - `dt_explorer/core/west_tools.py:17`: `DEFAULT_VENDORS = ("microchip", "atmel")`
   - `dt_explorer/ui/new_build.py:135,137`: placeholder `same54, pic32cx` and the label `Microchip/Atmel`
   - `dt_explorer/ui/page.py:124`: docstring example `build_same54_xpro` (example only)
5. **CLAUDE.md is partly outdated.** Its "Keep the single-file layout" convention and the architecture section
   describe the old single file. Not rewritten, because the write scope is one note.
6. **Dependency direction holds.** `core/` and `ui/` import no plugin package. The plugin packages import
   `dt_explorer.core` only. `core/translate.py` calls the registry in `core/plugins.py`, which is registry use
   and not a plugin import.
