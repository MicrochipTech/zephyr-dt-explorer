## What was done

| File | Change |
|---|---|
| `dt_explorer/core/port_report.py` | (1) `_rewrite_consumers`: for every enabled source node with a `phandle-array` property that references a ported node whose specifier names differ in the target binding (`specifier2cells`), the entry is rewritten by cell name (a new cell gets 0; a changed name takes over the value in order; a cell without counterpart is reported as dropped). Consumer in the target (same label, else same path): override block; consumer in app text that the port carries: override block after it (`&{path}`); consumer missing in the target: carried under its parent (when the parent exists, is okay, and no other property references a label the target lacks); else `report` with the exact line. Decisions in `PortReport.consumers` (`ConsumerFix`), printed as `consumer ...` lines in section 1. (2) uncovered enabled nodes that a board file or the app configures (`_set_by_user`: some property comes from a non-SoC file) are looked up in the registry: `no_target` -> `NodeResult` status `no_target`, line `untranslatable: <reason>`, also a Kconfig row; entry with a target -> section 5 `translation X -> Y exists, not ported because no recipe lifts the node ...`. |
| `dt_explorer/core/translate.py` | child rule key `rename: name[@hexunit]` (unit address sets `reg`, report line `child X renamed Y, reg = <0x..>`); entry key `default: {prop: {value, note}}` (written when no rule produced the property, report line `default 'p' ...`); both validated at load; docstring. |
| `dt_explorer/translations/atmel_sam0_to_mchp_g1.yaml/.py` | DAC children `channel_0/1` -> `rename: channel@0/1`; ADC `default: prescaler 4` (reminder removed from `target_only`); the DAC hook no longer reports the rename as the caller's part. |
| `tests/test_translate.py`, `tests/test_port_report.py` | 3 + 4 new translate tests (+ 1 real-edtlib test, negative ADC test adjusted), 11 new port tests, lab1 real-port test extended; DAC tests expect renamed children with `reg`. |

Decision (gap 2): an enabled, board-configured SoC node with a translation that has a target but no recipe is **not ported** by the translation but listed in section 5 as "translation exists, not ported because no recipe lifts the node". Reason: translating needs the draft node (pads, roles, clocks) that only a recipe produces; the translation alone would copy SoC-defined `reg`/`interrupts` of the source SoC into a target SoC. Nodes that only the SoC description enables (clock tree, pinctrl, gpio ports, pinmux) stay silent, as before.

Decision (section numbering): the consumer lines are part of section 1, not a section of their own: `ui/port.py` numbers sections by position and `tests/test_board_view.py` (outside this card) expects `1..5`; a separate `1b` section made that test fail (found in the first suite run).

Vendor-term grep, `grep -ciE "atmel|microchip|sercom|sam0|pic32|same5|sam_e54|g1"` (matching lines): `core/port_report.py` before 5, after 5; `core/translate.py` before 0, after 0.
