## Findings that the builder should know

1. **CAN and USB are not listed in the real lab1 port report.** The `no_target` entries exist and a draft node of either kind is reported as `no_target` with the reason (synthetic test `test_can_and_usb_are_untranslatable_in_the_port_when_they_are_in_the_draft`). lab1 has an enabled `usb0` (`zephyr_udc0: &usb0`) and disabled `can0/can1`, but `port_report.port_build` only looks at nodes that a recipe lifts into the draft; an enabled node without recipe is listed in section 5 only if its origin is not `soc`/`module`, and `usb0` has origin `soc`. So it appears nowhere. To list it, `port_report.py` would have to look up the registry for the uncovered nodes (a `no_target` entry gives the reason). Outside this card's write scope.
2. **Consumers' `pwms` are not rewritten.** `#pwm-cells` 2 to 3 is done on the controller with a report line; `translate.py` translates one node, `port_report.py` has no step for other nodes' `pwms`. In lab1 the consumer `/pwmleds` is in section 5 ("carry it over by hand").
3. The engine cannot (a) rename a child node and add `reg` from its name (DAC `channel_0` to `channel@0`), (b) give a default for a property the source node lacks (ADC `prescaler`, required on g1 and not in the SoC dtsi). Both are reported in lines; the port stays correct for lab1 because the target board file sets `prescaler`.
4. Bug found and fixed in the existing YAML: unquoted `zephyr,deferred-init, ..., zephyr,pm-device-runtime-auto, zephyr,disabling-power-states` in the `base` group's flow list were split at the commas. They are quoted now; a test pins it.
5. Deviations from the research tables are listed in `docs/research/peripheral_pairs.md` section 10.
