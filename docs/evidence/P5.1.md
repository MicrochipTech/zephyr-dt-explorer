Findings:
- Macro names have the same style as in the old port (`PB25D_SERCOM2_PAD0`, `PA9D_...` without leading zero, `PA0_GPIO` for GPIO). Only the definition differs: one line `#define NAME MCHP_PINMUX(b, 25, d, periph)` (lower-case port and mux, function `periph`/`gpio`) instead of `SAM_PINMUX(B, 25, D, ...)` with a continuation line. The regex of the formatter was changed accordingly; everything else (leading zero, header check, instance lookup, render_group, dtsi parsing) is copied from atmel_sam0.
- Integer encoding: `MCHP_PINMUX(port, pin, mux, func) = port | pin << 4 | func << 9 | periph << 12` (func gpio 0, periph 1, extra 2, system 3, lpm 4, wakeup 5; port a=0, mux a=0). `pinmux_value()` reproduces it; PB25D = 13201 (tested). The formatter itself only needs the names.
- Header location differs from hal_atmel: `dt-bindings/sam/sam_d5x_e5x/<atsame54>/<atsame54p20a>-pinctrl.h`, found by `find_header(ws, "same54p20a")`.
- The new header contains the 4 SERCOM7 macros that hal_atmel lacks (PB30C_SERCOM7_PAD0, PB31C_SERCOM7_PAD1, PA30C_SERCOM7_PAD2, PA31C_SERCOM7_PAD3), so all 134 SERCOM signals round trip (old formatter: 130).
- Cross-check: 130 identical names, 0 differing names, 0 only-old, 4 only-new (the SERCOM7 ones). No example of a differing name exists for SERCOM; the 92 old-only names in P5.0 concern other pins/peripherals, not SERCOM signals.
- Duplication: helpers (zephyr_pad, neutral_pad, load_header cache, parse_dtsi_groups, ParsedPin, FormatterError) are copied from atmel_sam0.py, not shared; `FormatterError` is a separate class (the cross-check test catches both).
- `formatters/__init__.py` was not touched; it may need an import line `microchip_port_g1` so the formatter registers on package import.
