## Modules

* `dt_explorer/recipes/adc.py`: recipe `adc` (`atmel,sam0-adc`, `microchip,adc-g1`); class `adc` (`adc-controller.yaml`).

| Item | PWM | ADC |
|---|---|---|
| roles | `WO0..WO7` (TCC), `WO0..WO1` (TC); role = ATDF signal name; instance kind `TCC`/`TC` | `AIN0..AIN15`; role = ATDF signal name; kind `ADC` |
| `derived_props` | checks only (pad signal == role, range); returns `{}` | same |
| derived from pad | PWM channel of a consumer = output mod channels (`pwm_channel`) | `zephyr,input-positive` = AIN number of the role (`channel_child`, `channels_for`), `reg` defaults to it |
| `#pwm-cells` | 2 old / 3 g1 (`pwm_cells`, in `default_props`; renderer also adds it from the binding const) | - |
| `prescaler` | chosen: `suggest_prescaler(gclk, period, bits)`, default 8 | g1 required (SoC lacks it): `suggest_prescaler(gclk)` (<= 16 MHz), default 4 at 60 MHz; old: SoC has 4 |
| other defaults | old TC: `channels` 2, `counter-size` 16; g1 TCC0/1: `max-bit-width` 24 | children: gain, reference, acquisition-time, resolution, optional vref-mv, differential |
| Kconfig | `CONFIG_PWM` + `PWM_SAM0_TCC` / `PWM_SAM0_TC` / `PWM_MCHP_G1_TCC` / `PWM_MCHP_TC_G1` (all have prompts) | `CONFIG_ADC` + `ADC_SAM0` / `ADC_MCHP_G1` |
| `valid_assignments` | all 255 (TCC) / 3 (TC) subsets | subsets up to 4 inputs (2516) to keep the UI pad lists fast |

## Findings

1. **ADC0 pins cannot be rendered.** On ADC0 every AIN pad also carries the PTC signals `X<n>`/`Y<n>` (and VREFA/B/C) with the same mux letter; `core/render._signals` raises `pad ... offers N signals on ADC0`. ADC1 has AIN only and works (this evidence). Lift of SG41 `adc0` works but cannot render back. Fix belongs in core (`render._signals`: prefer the signal whose role the recipe accepts) or in the provider (drop PTC signals). Unit test `test_render_refuses_a_pad_with_several_signals_on_the_instance` pins the current behaviour.
2. **lift puts `phandle = <N>` into `vendor_props`** for a node that a consumer references (tcc0 via pwm-leds). The renderer writes `phandle = <16>;`; the compare passes only because the number is identical. `core/lift.py` skips `phandle` for children but not for nodes.
3. **`#pwm-cells` is a neutral property** (declared in `pwm-controller.yaml`): the lift puts it in `props` and `ui/configure.neutral_specs` would offer it as a field; add it to `NOISE_PROPS`. The draft value (2) is not portable to g1 (3): P8.10's translation must transform it.
4. `class_options` takes the first available compatible per class, so on SG41 (main still contains the atmel bindings) `options_for` offers `atmel,sam0-*-pwm` / `atmel,sam0-adc`. The acceptance builds the option explicitly with the g1 compatible. Same effect exists for the SERCOM recipe.
5. The configurator dialog cannot add children and `build_node` leaves `vendor_props` empty, so prescaler/`#pwm-cells`/children come from `recipe.default_props()` and `adc.channels_for()` (used by the acceptance scripts); a UI card must call them.
6. The board's pinctrl group `pwm_default` is rendered as `tcc0_pwm_default`; the compare normalises group names (pinmux values equal).
7. The reset devicetree of tcc0 does not compile (`pwms = <&tcc0 ...>` of pwm-leds lacks `#pwm-cells`), same precedent as P8.4; for adc0 the reset differs by status.
