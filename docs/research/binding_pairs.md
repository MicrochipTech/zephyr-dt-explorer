# P5.0 Research: binding pairs `atmel,sam0-*` <-> `microchip,*-g1`

Research only (card P5.0). Basis for the translation format in P5.2. No code is changed.
Every table row is one property of the source binding (own and inherited) and states its counterpart, the target type and required flag, and the mapping. Evidence and counts: `docs/evidence/P5.0.md`.

## 2. Findings (read first)

1. **No g1 I2C or SPI binding or driver exists in v4.3.0.** The new SoC dtsi gives SERCOM7 the compatible `microchip,sercom-g1-i2c` (`samd5xe5x_p.dtsi:33`, `samd5xe5x_n.dtsi:33`), but there is no YAML and no driver for it. There is no g1 SPI binding at all. Tables 1.2 and 1.3 are therefore source-only with mapping `open`. P5.2 cannot translate I2C or SPI from this workspace. This is a stop-condition-4 matter (design silent on the target) unless `zephyr-main` provides the bindings.
2. **`sam_e54_xpro` configures only UART (SERCOM2), pinctrl, TCC0 and the clock tree.** The old `same54_xpro` also configures SERCOM4 SPI and SERCOM7 I2C (with an EEPROM child). So the planned check "same54_xpro -> sam_e54_xpro" has no reference values for I2C or SPI on the new side.
3. **The clock tree moved from C code and Kconfig into devicetree.** Old: `gclk`, `mclk` and `osc32kctrl` are bindings with cells (`<&gclk ID>`, `<&mclk OFFSET BIT>`). The generator is chosen on the consumer by `atmel,assigned-clocks`, and DFLL, DPLL and XOSC setup is in `soc/atmel/sam0/common/soc_samd5x.c` plus SoC Kconfig. New: one `microchip,sam-d5x-e5x-clock` node with nine child kinds. Consumers use `<&mclkperiph SUBSYS>, <&gclkperiph SUBSYS>`, and `atmel,assigned-clocks` has no equivalent (it becomes `gclkperiph-src` on the clock child). Every SERCOM needs a derive rule.
4. **`clock-names` and order change.** Old `clocks = <&gclk N>, <&mclk O B>` with names `GCLK`, `MCLK`. New `clocks = <&mclkperiph>, <&gclkperiph>` with names `mclk`, `gclk`. The old driver looks names up with `DT_INST_CLOCKS_CELL_BY_NAME(n, gclk, id)` (`uart_sam0.c:1278`). P5.3 has to confirm that the lookup still works with the new names.
5. **RTC source value (surprise).** The old board sets `atmel,assigned-clocks = <&osc32kctrl 4>` (`same54_xpro.dts:80`), and the old binding example says "Connect the XOSC32K to RTC on SAMD5x" with the same 4. The RTCSEL encoding in the ASF headers (samd51 and samc20) is 4 = `XOSC1K` (1.024 kHz) and 5 = `XOSC32K`. The new `rtc-src` uses the same numbers (4 = xosc1k, 5 = xosc32k), so the value carries over unchanged. The old example comment looks wrong, and the old board's RTC runs from the 1 kHz output. This was checked against the ASF headers only, not against the SAME5x datasheet, which is not among the sources.
6. **Pin macro names.** For SERCOM pads, all 130 old SERCOM names exist in the new header. The new header adds SERCOM7 PAD2/PAD3 on PA30, PA31, PB30 and PB31. Across the whole header, 632 names are common, 92 exist only in the old header (for example `PA10B_PTC_XY8`, `PA10I_SDHC0_DAT1`, `PA10J_IIS_SCK0`, `PA14M_GLKC_IO0`), and 125 only in the new one (for example `PA10B_ADC0_X8`, `PA10I_SDHC0_SDDAT1`, `PA10J_I2S_SCK0`, `PA14M_GCLK_IO0`). The board macros used (PB24D, PB25D, PB26D, PB27D, PB29D, PC18F, PD8C, PD9C, PA25H, PA24H, PA2B, PA5B) exist on both sides. The macro body changes from `SAM_PINMUX(...)` to `MCHP_PINMUX(...)`, which is a body change, not a value change.
7. **Old pinmux nodes have no counterpart.** The old SoC has `pinmux_a..pinmux_d` nodes (`samd5x.dtsi:151-167`). The new port has one pinctrl node with `ranges` and no pinmux children.
8. **Old UART and I2C/SPI DMA and collision handling differ in the drivers.** `collision-detection` is read by `uart_sam0.c:1268` and not by `uart_mchp_sercom_g1.c`. `dmas`/`dma-names` are read by the old UART, I2C and SPI drivers, but the g1 UART driver has no DMA code. Both properties stay in the table as `keep` because the binding is unchanged, but P5.2 must decide whether to translate or drop them.
9. **Node compatibles.** The old board overrides only the SERCOM node's `compatible`. The new board does the same with `microchip,sercom-g1-uart`, while the SoC default stays `microchip,sercom-g1`. The old SoC node has `atmel,assigned-clocks`, the new one does not.

The driver enable symbols are `default y` on both sides, gated by `DT_HAS_*_ENABLED`, so a DT node is what turns a driver on.

## 5. Node structure differences

| Aspect | Old (`atmel,sam0`) | New (`microchip,*-g1`) |
|---|---|---|
| SERCOM SoC compatible | `atmel,sam0-sercom` (`samd5x.dtsi:177-265`) | `microchip,sercom-g1` (`samd5xe5x.dtsi:94-233`); SERCOM7 `microchip,sercom-g1-i2c` (no binding) |
| `clocks` cells | `<&gclk ID>` (1 cell), `<&mclk OFFSET BIT>` (2 cells) | `<&mclkperiph SUBSYS>` (1 cell), `<&gclkperiph SUBSYS>` (1 cell) |
| `clock-names` | `GCLK`, `MCLK` | `mclk`, `gclk` |
| `clocks` order | GCLK first | MCLK first |
| Generator selection | `atmel,assigned-clocks = <&gclk N>` on the consumer | `gclkperiph-src = "gclkN"` on the child in `&clock` |
| Clock controllers | three nodes: `gclk@40001c00`, `mclk@40000800`, `osc32kctrl@40001400` | one `clock@40000800` with children (`xosc`, `dfll`, `fdpll`, `rtcclock`, `xosc32k`, `gclkgen`, `gclkperiph`, `mclkcpu`, `mclkperiph`) |
| Pin controller | `atmel,sam0-pinctrl@41008000` with `#atmel,pin-cells` on GPIO children | `microchip,port-g1-pinctrl@41008000` with `#microchip,pin-cells` on GPIO children |
| Pin mux nodes | `pinmux_a..d` (`atmel,sam0-pinmux`) | none |
| Pin macro body | `SAM_PINMUX(...)` (`same54p-pinctrl.h`) | `MCHP_PINMUX(...)` (`atsame54p20a-pinctrl.h`) |
| GPIO register block | `0x41008000 0x80` (same addresses) | same |
| SERCOM register size | `0x40` (`samd5x.dtsi`) | `0x31` (`samd5xe5x.dtsi`) |

## 7. Open points and gaps (input for P5.2 and later)

- **I2C and SPI have no target** in v4.3.0 (tables 1.2, 1.3). Check the new Zephyr main workspace (`C:\Masters\zephyr-main`, planned for P6.1) or record a decision.
- **Clock derive rules** (all need the header `mchp_sam_d5x_e5x_clock.h`): GCLK id -> `CLOCK_MCHP_GCLKPERIPH_ID_*` (GCLK 23 is SERCOM2_CORE: `MCHP_CLOCK_DERIVE_ID(6, 0x3f, 0x3f, 23, 30)`), MCLK (OFFSET, BIT) -> `CLOCK_MCHP_MCLKPERIPH_ID_*` (`0x14` is APBA, `0x18` is APBB; bit 9 on APBB is SERCOM2; the derive macro encodes bus index and bit). The bus index mapping rests on two examples and must be checked against all four buses. Generator index `N` -> `CLOCK_MCHP_GCLKGEN_ID_GENn`.
- **RTC source 4 vs 5** (finding 5): carry the value unchanged (4 = xosc1k), but confirm on the SAME5x datasheet and correct the old binding comment if needed. Out of the card's scope: the RTC binding itself (`atmel,sam0-rtc`).
- **Pin macro renames**: 92 old-only names need a rename map for pinmux transforms (P5.2). The 4 new SERCOM7 pads (PA30, PA31, PB30, PB31) only matter for SERCOM7 (I2C, open).
- **`dmas` / `dma-names` on g1 UART**: no DMA support in `uart_mchp_sercom_g1.c`. Decide keep-and-ignore or drop.
- **`clock-names` case**: old names are upper case (`GCLK`, `MCLK`), new are lower case. Zephyr's `DT_*_BY_NAME` macros take lowercase tokens (`atmel_sam0_dt.h:127`). Confirm in P5.3 that the old driver's lookup works with the new names (or change the names in the translation).
- **Target-only defaults**: `run-in-standby-en` (default 1), `clock-external` (no default), `on-timeout-ms` (default 5). These must be listed in the translation as explicit "no counterpart" entries, so the translator does not drop or invent them silently.
- **Clock sub-bindings have no old DT counterpart**: `dfll`, `fdpll`, `xosc`, `xosc32k`, `gclkgen`, `mclkcpu`, `rtc` values come from SoC C code and Kconfig in the old port. The E54 board sets only a few of them, so the translation needs a defaults file, not a copy.
- **Board `status` of GPIO nodes**: the new SoC sets `status = "disabled"` on `portb` and `portc`, and the E54 board enables them. The old board does not touch the ports. Both are fine for translation but must be noted when lifting.
